Annotate research papers with a model that runs on your computer

fyrno7 reads a PDF the way a careful reader does. It underlines the claims, circles the jargon and questions weak reasoning in the margin. Then it writes a TL;DR, decodes the acronyms and drafts a notes document. Scanned papers are read with built-in OCR.

What it produces

Choose any combination. One pass over the paper generates everything, and you can switch between views afterwards.

Sharpie view
Circles, underlines, squiggles and handwritten margin notes drawn over your PDF. Your original file is never changed.
Professional view
Color coded highlights with numbered comments. Each comment carries a category and a severity, so a reviewer can scan for the major issues first.
Companion notes
A separate document with an overview, key results, strengths, weaknesses and questions for the authors. Export it as Markdown or HTML.
TL;DR
A one sentence summary, the key points and a plain language version. A reader level setting controls how much background it assumes.
Acronym decoder
Definitions the paper writes out are found with pattern matching and labelled as defined in the paper. Only the remaining abbreviations go to the model, and those are labelled as inferred.
Quote checking
Every passage the model quotes must exist in the PDF text. A quote that cannot be found is dropped before anything is drawn on the page.
Scanned papers
Pages without selectable text are read by an OCR engine bundled with the app. It runs on your computer and needs no download. Accuracy is best on clean, upright pages in English or other Latin scripts.
Summary PDF
Export the TL;DR, the acronyms and every annotation, grouped by page, as a new PDF. You can also print the annotated pages to PDF or save the annotations as JSON.

How it works

  1. Start a model server

    Run LM Studio or Ollama with a model such as Gemma 3. fyrno7 talks to any server that speaks the OpenAI API.

  2. Open a paper

    Drop in a PDF. Pages without selectable text are read with OCR first, and the paper is split into chunks that fit your model.

  3. Choose what you want

    Pick Sharpie, Professional, a companion document, a TL;DR and acronym decoding in any combination, then press Annotate.

  4. Read and export

    Switch views, filter by category, delete annotations you disagree with and export the results.

Your papers stay on your computer

fyrno7 has no accounts and sends no telemetry. The only network connection the app makes is to the model server address you set, which is on your own machine by default. OCR runs inside the app.

If you point fyrno7 at a remote server, the text of the paper goes to that server, so choose it with that in mind. The Privacy Policy lists exactly what is stored and where.

The source is public, so you can check all of this yourself. fyrno7 is released under the MIT license.

Set up a model

fyrno7 needs a local model server. Any OpenAI compatible server works, for example LM Studio, Ollama, llama.cpp's llama-server, Jan, KoboldCpp or vLLM. Two common setups:

LM Studio

  1. Install LM Studio and download a Gemma 3 model. The 4B size is fast, and 12B or 27B give better judgement.
  2. Open the Developer tab, load the model, set the context length to at least 8192 and start the server.
  3. In fyrno7 open Settings, choose LM Studio and press Detect models.
http://localhost:1234

Ollama

  1. Install Ollama and keep it running.
  2. Download a model:
ollama pull gemma3
  1. In fyrno7 open Settings, choose Ollama and press Detect models. The server address is:
http://localhost:11434

First launch

Windows

If SmartScreen shows "Windows protected your PC", choose More info and then Run anyway. The builds are not code signed yet.

macOS

Open the disk image and drag fyrno7 to Applications. Then right click the app and choose Open. If macOS says the app is damaged, remove the quarantine flag in Terminal:

xattr -dr com.apple.quarantine /Applications/fyrno7.app
Linux

Make the AppImage executable and run it:

chmod +x fyrno7-linux-x86_64.AppImage && ./fyrno7-linux-x86_64.AppImage

For the packages, use your package manager:

sudo apt install ./fyrno7-linux-amd64.deb sudo dnf install ./fyrno7-linux-x86_64.rpm

Build from source

You need Rust (stable). On Windows you also need the MSVC build tools, and WebView2 ships with Windows 11. On Linux install the Tauri prerequisites.

git clone https://github.com/realaaravdas/fyrno7.git cd fyrno7/src-tauri cargo run --release

Run cargo test to execute the backend tests.

Questions

Is my paper kept private?

fyrno7 only talks to the model server you configure, which normally runs on your own computer. There are no accounts, no analytics and no cloud calls. If you point it at a remote server, the text goes there.

Do I have to use Gemma?

No. Gemma 3 is a good default, and any chat model behind an OpenAI compatible endpoint works. Larger models usually give sharper annotations.

What hardware do I need?

That depends on the model you choose. Small quantised models of about 4B parameters run on most recent laptops. 12B and 27B models want a capable GPU or plenty of memory. fyrno7 itself is light.

How long does a paper take?

It depends on your model and hardware. The paper is processed in chunks, and a progress bar shows a percentage and a time estimate. You can cancel at any time, and a chunk that fails only costs you that chunk.

Can the model make things up?

Every quote is checked against the PDF text, and anything that cannot be found is discarded. The judgement itself, such as "this looks weak", is still the model's opinion. Treat it as a well read colleague's margin notes and delete any annotation you disagree with.

Does it change my PDF?

No. Annotations are drawn on top of the page inside the app. To keep them, export a Summary PDF or print the annotated pages to a new PDF.

How does the acronym decoder work?

Definitions written in the paper, such as "Stochastic Gradient Descent (SGD)", are found with pattern matching. Only abbreviations the paper never defines are sent to the model, and they are labelled as inferred. When the model is unsure it leaves the expansion empty.

Does it work on scanned PDFs?

Yes. If a page has no selectable text, fyrno7 runs OCR on it before annotating. The OCR engine and its models are inside the app, so nothing is downloaded or uploaded. Skewed or low resolution scans give rougher text.

Which systems are supported?

Windows, macOS (Apple Silicon and Intel) and Linux builds are published with each release. The macOS and Linux builds come from automated builds and have not been tested on real machines by the maintainer yet, so please report problems.

Is it open source?

Yes. The source is on GitHub under the MIT license. Issues and pull requests are welcome.
